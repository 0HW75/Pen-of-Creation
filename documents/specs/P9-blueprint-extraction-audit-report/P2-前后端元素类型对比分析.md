### 3.2 差异分类

#### 第一类：前端缺失，后端支持（5种）

这些类型在前端无法选择提取，但后端已实现支持：

| 类型 | 后端提取器状态 | 说明 |
|------|--------------|------|
| `civilizations` | ✅ 已实现 | 文明 |
| `social_classes` | ✅ 已实现 | 社会阶层 |
| `political_systems` | ✅ 已实现 | 政治体系 |
| `economic_systems` | ✅ 已实现 | 经济体系 |
| `cultural_customs` | ✅ 已实现 | 文化习俗 |

**影响**：用户无法通过前端提取文明、社会阶层、政治体系、经济体系、文化习俗这5种设定元素。

#### 第二类：前端有，后端不存在（1种）

| 类型 | 前端状态 | 后端状态 | 说明 |
|------|---------|---------|------|
| `society_systems` | 硬编码 | **不存在** | 这是一个**旧名称**，后端已拆分为多个类型 |

**原因分析**：
- `society_systems` 是旧的功能名称
- 后端重构后将其拆分为 `civilizations`（文明）、`social_classes`（社会阶层）等更具体的类型
- 前端代码未同步更新，仍使用旧名称

### 4.2 后端返回的 statistics 键名

**文件位置**：`backend/app/api/worldview_extraction.py` L79-88

```python
statistics = {
    'characters': len(extracted_elements.get('characters', [])),
```

**注意**：statistics 中也**没有** `society_systems`！

### 4.3 结论

**原审查报告中有一个错误描述需要修正**：

❌ 原描述：`statistics` 返回 `society_systems` 但 `elements` 中没有
✅ 修正后：`statistics` 和 `elements` 的键名**完全一致**，都**没有** `society_systems`

前端发送的 `society_systems` 会被后端**忽略**，因为提取器根本不使用这个类型名。
